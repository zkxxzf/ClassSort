## 一、算法总览

教务分班软件的核心目标是：**将 N 名学生均匀分配到 M 个班级，使各班在总分、单科、分段、类别等维度上的偏差最小化**。

### 1.1 算法流程

```
输入数据 → 预处理 → 初始分配 → 迭代优化 → 终局微调 → 输出结果
```

| 阶段 | 说明 | 关键方法 |
|------|------|----------|
| 预处理 | 约束构建、班型筛选、捆绑代表、姓名冲突 | `_apply_class_types()` |
| 初始分配 | 蛇形分配（Snake Draft）保证分段均衡 | `_initial_assign()` |
| 迭代优化 | 多轮迭代，每轮执行 4 种操作 | `_optimize()` |
| 终局微调 | 纯均分精调，逼近 0.01 均分偏差 | `_mean_polish()` |
| 后处理 | 约束满足 + 均分精调 | `_post_process()` |

### 1.2 核心类结构

```
BalanceEngine (分班引擎)
├── _ClassStats (班级统计缓存，增量更新)
├── ConstraintManager (约束管理器)
│   ├── BindingGroup (同班捆绑组)
│   ├── MutexGroup (互斥分散组)
│   └── NameConflict (姓名同音冲突)
└── TaskConfig (任务配置)
    ├── 权重 (w_total, w_subject, w_segment, ...)
    ├── 容差 (tol_mean, tol_count)
    ├── 班型 (class_types)
    └── 自定义分段 (segment_rules)
```

## 二、当前成本（Cost）详解

### 2.1 什么是"当前成本"

**当前成本**是衡量分班结果"好坏"的唯一综合指标。成本越低，说明分班结果越均衡、越合理。

算法的所有优化操作（换班、移班）都以**降低成本**为目标。每次换班后，如果新成本 < 旧成本，说明换班有效；反之则回退。

### 2.2 成本计算公式

```
总成本 = w_size × 人数偏差 + w_total × 总分均分偏差 
       + w_subject × Σ(单科均分偏差) + w_segment × 分段人数偏差 
       + w_category × 类别人数偏差 + w_pointwise × 逐点偏差 
       + 硬约束违反度
```

### 2.3 各项偏差的计算方式

#### （1）人数偏差
```
size_dev = max(各班人数) - min(各班人数)
```
权重 `w_size` 控制人数均衡的重要性。

#### （2）总分均分偏差
```
total_dev = max(各班总分均分) - min(各班总分均分)
```
权重 `w_total` 通常设置较高（200.0），确保总分均衡为首要目标。

#### （3）单科均分偏差
```
subject_dev = max(各科 max均分偏差) 
           + 其他科目的均分偏差之和
```
每个单科独立计算 `max - min`，乘以该科的调节因子 `metric_adjust`。

#### （4）分段人数偏差
```
segment_dev = max(各分段内 max班级人数 - min班级人数)
```
将学生按总分分为高/中/低三段（各占1/3），计算每段内各班人数的最大差值。

#### （5）类别人数偏差
```
category_dev = max(各类别值的 max班级人数 - min班级人数)
```
对每个类别字段（如性别、民族）的每个取值（如"男"/"女"），计算各班人数的最大差值。

#### （6）逐点偏差
```
pointwise_dev = Σ|各班高低分学生数差异|
```
衡量各班高分段/低分段学生分布的均匀性，防止出现"尖子班"和"差班"。

#### （7）硬约束违反度
```
hard_penalty = 捆绑违反 × 1000 + 互斥违反 × 500 + 姓名冲突违反 × 200
```
硬约束必须严格满足，违反度作为成本的"惩罚项"，确保算法优先满足约束。

### 2.4 成本在班型模式下的特殊处理

**当配置了班型（如重点班/普通班）时，成本的各项偏差按班型组分别计算：**

```python
# 例如：重点班(1班,2班) 和 普通班(3班,4班,5班)
# 总分均分偏差 = max(重点班组内偏差, 普通班组内偏差)
# 而不是跨所有班级计算
```

这样做的好处是：
- 重点班内部学生水平相近，组内偏差可以做到极小（0.01 以内）
- 不同班型之间的天然差异（如重点班均分远高于普通班）不会计入成本
- 算法专注于优化各班型内部的均衡性

## 三、迭代次数的设计思路

### 3.1 什么是迭代次数

**迭代次数**是优化算法的最大迭代轮数。每轮迭代依次执行 4 种操作：

| 操作 | 说明 | 作用 |
|------|------|------|
| 定向换班 | 针对最大偏差的班对，寻找最优交换 | 快速降低偏差 |
| 单人移班 | 将极端分值学生从偏差过大的班移到偏差最小的班 | 消除极端值影响 |
| 贪心换班 | 遍历所有学生对，贪心选择降低成本的交换 | 全局搜索优化 |
| 终局微调 | 纯均分优化（后半程启动） | 逼近均分容差 |

### 3.2 收敛判断

每轮迭代后检查：
```
if 当前成本 < 最佳成本 - 1e-9:
    更新最佳解
    无改进计数 = 0
else:
    无改进计数 += 1

if 连续30轮无改进:
    模拟退火扰动（从最佳解出发，随机打乱）
    无改进计数重置

if 均分偏差 ≤ 容差目标(0.01):
    提前收敛，不必跑完所有迭代
```

### 3.3 迭代次数的建议设置

| 学生数 | 建议迭代次数 | 说明 |
|--------|-------------|------|
| ≤ 100 人 | 100-200 | 数据量小，收敛快 |
| 100-300 人 | 200-300 | 默认值 300 通常足够 |
| 300-600 人 | 300-500 | 数据量大，需要更多迭代 |
| ≥ 600 人 | 500-800 | 大数据量，建议增加迭代 |

**注意事项：**
- 超过 500 次后边际收益递减，多数情况下 300 次已达到最优或近最优
- 如果多次运行后偏差仍较大，可适当增加迭代次数
- 迭代次数为 0 时使用默认值 300
- 迭代过程中若达到容差目标会提前结束

### 3.4 迭代与成本的关系

```
成本
 │    ╱╲        ← 模拟退火扰动（跳出局部最优）
 │   ╱  ╲      ╱╲
 │  ╱    ╲    ╱  ╲
 │ ╱      ╲  ╱    ╲
 │╱        ╲╱      ╲───────────→ 迭代次数
 │                              收敛到最佳解
 └────────────────────────────────
```

典型的成本下降曲线：
1. **前 50 轮**：成本快速下降（定向换班、贪心换班效果显著）
2. **50-150 轮**：成本稳步下降，出现多次模拟退火
3. **150-300 轮**：成本趋于稳定，偶有扰动后快速回落
4. **300 轮后**：基本收敛，继续迭代收益极小

## 四、班型分层分班算法

### 4.1 班型筛选

```python
# 按优先级（rank_floor 升序）分配学生到班型
for spec in sorted_specs:
    # 计算有效 rank_ceil（含同分扩展）
    r_ceil = spec.rank_ceil
    while r_ceil < len(students) and students[r_ceil].score == students[r_ceil-1].score:
        r_ceil += 1  # 同分学生全部纳入
    # 分配学生
    for student in students:
        if student.rank in [r_floor, r_ceil] and not already_assigned:
            assign_to(student, spec)
```

**关键设计**：
- **同分扩展**：rank_ceil 处若有同分，同分学生全部纳入该班型，保证公平
- **优先级**：rank_floor 越小优先级越高（重点班 > 卓越班 > 普通班）
- **唯一归属**：每个学生只分配到一个班型（第一个匹配的）

### 4.2 班型组分段

```python
# 每个班型组独立计算分段
for group in class_type_groups:
    group_students = filter_by_group(group)
    group_students.sort(by=total_score, reverse=True)
    n = len(group_students)
    c1, c2 = n // 3, n * 2 // 3  # 三等分
    for rank, student in enumerate(group_students):
        if rank <= c1: segment = 0  # 高分段
        elif rank <= c2: segment = 1  # 中分段
        else: segment = 2  # 低分段
```

### 4.3 班型组内优化

迭代优化时，每种偏差指标都在班型组内独立计算：
```python
# 总分均分偏差（按班型组）
for group in class_type_groups:
    dev = max(group_means) - min(group_means)
    cost += w_total * dev²

# 分段偏差（按班型组）
for group in class_type_groups:
    seg_dev = max(segment_counts) - min(segment_counts)
    cost += w_segment * seg_dev
```

## 五、约束系统

### 5.1 约束类型

| 约束 | 说明 | 违反惩罚 |
|------|------|----------|
| 同班捆绑 | 组内学生必须同班 | 1000/人 |
| 互斥分散 | 组内学生必须不同班 | 500/人 |
| 姓名同音 | 读音相同学生分散 | 200/人 |
| 预设班级 | 指定学生分到指定班 | 硬约束 |
| 班型约束 | 重点班学生只能进重点班 | 硬约束 |

### 5.2 约束检查流程

```python
def validate(students, num_classes):
    # 1. 检查捆绑组是否同班
    for group in bindings:
        if group.students_in_different_classes:
            report_violation()
    
    # 2. 检查互斥组是否分散
    for group in mutexes:
        if group.students_in_same_class:
            report_violation()
    
    # 3. 检查预设班级
    for student in students:
        if student.preset_class != student.assigned_class:
            report_violation()
```

## 六、蛇形分配（初始分配）

### 6.1 基本思想

将学生按总分降序排列，采用蛇形（S 形）分配到各班：

```
班级:  1班  2班  3班  4班  5班
       ─────────────────────
第1轮:  S1  S2  S3  S4  S5    (正向)
第2轮:  S10 S9  S8  S7  S6    (反向)
第3轮:  S11 S12 S13 S14 S15   (正向)
...
```

### 6.2 蛇形分配的优势

1. **天然保证分段均衡**：每轮分配的学生分数相近，各班在每轮中各得一名
2. **快速收敛**：初始分配已经较为均衡，后续优化只需微调
3. **可扩展性**：支持捆绑组作为整体分配（捆绑代表）

## 七、模拟退火策略

### 7.1 触发条件

当连续 30 轮迭代没有改进（成本未下降）时触发。

### 7.2 退火过程

```python
if no_improve >= 30:
    # 从历史最佳解出发
    assignment = best_assignment.copy()
    # 计算温度（随迭代次数递减）
    temperature = max(0.5, 3.0 - iteration * 0.005)
    # 执行退火操作：随机扰动
    _anneal(assignment, temperature)
    no_improve = 0
```

### 7.3 温度衰减

温度从 3.0 线性衰减到 0.5，控制扰动强度：
- **高温**（早期）：大幅扰动，跳出局部最优
- **低温**（晚期）：小幅调整，精细优化
